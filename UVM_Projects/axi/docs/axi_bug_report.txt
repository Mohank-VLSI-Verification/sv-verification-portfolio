# AXI UVM Verification — Bug Report v1.0

## 1. Scope

End-to-end verification of an AXI4 memory-mapped slave, exercising:
- Fixed burst (`awburst=00`, 8 beats, addr=5)
- Incremental burst (`awburst=01`, 8 beats, addr=5)
- Wrap burst (`awburst=10`, 8 beats, addr=5)
- DECERR path (addr=128, out-of-range access)
- Reset behavior and reset-mode transactions
- Protocol handshake invariants via 5 SVA assertions covering `awvalid`/`wvalid`/`bvalid`/`rvalid` stability rules and `awburst` legality
- Functional coverage closure via `uvm_subscriber`-based collector, connected inside the agent

DUT: `axi_slave` (four independent FSMs — `awstate`, `wstate`, `bstate`, `arstate`/`rstate` — driving a 128-byte memory array with byte-strobed writes and burst-mode reads)
Reference model: `ref_model` (128-entry mirror array, predicts `bresp`/`rresp` from `awaddr`)

## 4. Bugs Found and Fixed (Testbench)

### Bug TB-1 — `uvm_sequence_library::execute()` Null Deref (Fifth Confirmation)

**Symptom:** Original test used `axi_seq_lib extends uvm_sequence_library #(transaction)` with 5 typewide-registered sequences and called `seqlib.start(e.a.seqr)`. Same failure mode as APB (TB-3), I2C (TB-2), UART (TB-1), and SPI (TB-1) — Vivado XSIM 2025.2's UVM 1.2 implementation of `uvm_sequence_library::execute()` dereferences an internal handle that `init_sequence_library()` does not populate.

**Root cause:** `add_typewide_sequence()` calls in the library constructor register the sequence wrappers correctly, but `execute()` cannot resolve them at runtime — `create_seq_by_typename` returns null. Independently reproduced on all five protocols.

**Fix:** Retained `axi_seq_lib` class in source (documentation of intent) but rewrote the `test` class to execute sequences sequentially in `run_phase`, interleaved with reset sequences (see DUT-1 workaround in §5).

**Verification:** Clean run — all sequences executed, 4 bursts driven, 0 UVM_ERROR.

---

### Bug TB-2 — `assert(tr.randomize)` Legacy Pattern in All 5 Sequences

**Symptom:** All 5 sequence bodies (`rst_dut`, `valid_wrrd_fixed`, `valid_wrrd_incr`, `valid_wrrd_wrap`, `err_wrrd_fix`) used the legacy `assert(tr.randomize);` idiom. Randomization failure would fire a simulation-terminating VLOG assertion error rather than a controlled UVM_ERROR.

**Fix:** Replaced across all 5 call sites with the UVM-idiomatic guard:
```
if (!tr.randomize()) `uvm_error("SEQ", "randomize failed")
```
**Verification:** Zero randomize failures on this run; guard is in place for future constraint additions.

---

### Bug TB-3 — Coverage Subscriber Instantiated in Env, Not Agent

**Symptom:** Original testbench declared `axi_coverage cov;` inside `env` and connected `a.m.send.connect(cov.analysis_export)` in `env::connect_phase`. Same limitation flagged in I2C bug report Known Limitation #2, UART TB-4, and SPI TB-3.

**Fix:** Moved `axi_coverage cov;` declaration and instantiation into `agent`. Connection is now agent-local:
```
// inside agent::connect_phase
m.send.connect(cov.analysis_export);
```
**Verification:** Clean run, coverage subscriber active in agent, `report_phase` reports 94.44%.

### Bug TB-4 — Driver FSM-Sync Timing Bug: Missing `@(posedge vif.clk)` in Three Write Tasks

**Symptom:** After `wrrd_fixed_wr` completed successfully, simulation hung indefinitely at the start of `wrrd_incr_wr` — driver blocked on `@(posedge vif.wready)`, DUT's `wstate` FSM stuck in `wstart` state waiting for the driver to align to the FSM transition boundary.

**Root cause:** `wrrd_fixed_wr` had an extra `@(posedge vif.clk);` immediately after its signal-setup block, giving the DUT's `wstate` FSM one clock to advance from `wstart → waddr_dec → wreadys`. The other three write tasks — `wrrd_incr_wr`, `wrrd_wrap_wr`, `err_wr` — were missing this synchronization clock, so they immediately called `@(posedge vif.wready)` while the FSM was still in `wstart` state.

**Fix:** Added one line to each of the three affected tasks, matching `wrrd_fixed_wr`:
```
vif.arvalid <= 1'b0; vif.rready <= 1'b0;  vif.bready <= 1'b0;
@(posedge vif.clk);                        // FSM advance beat
@(posedge vif.wready);
```
**Verification:** All four burst types now complete without hangs. First burst 45 ns → 645 ns, subsequent bursts complete in ~300 ns each.

### Bug TB-5 — Monitor and Ref-Model Read `vif.awaddr` Before `wait(awvalid)` (Race Condition Causing MISCMP)

**Symptom:** First run after TB-4 fix produced `[MISCMP] 2` and one `[SCO] Test FAILED  op:wrrdfixed addr:128 bresp:3/0 rresp:3/0`. DUT correctly returned DECERR (`bresp=3`, `rresp=3`) for the out-of-range address, but scoreboard tagged the operation as `wrrdfixed` with predicted `bresp=0`, causing a false-positive DUT failure.

**Root cause:** Both `mon.run_phase` and `ref_model.run_phase` had their branching structured as:
```
else if(vif.resetn && vif.awaddr < 128) begin
  wait(vif.awvalid == 1'b1);
  ...
```
The `awaddr` value was sampled at the posedge clk **before** `awvalid` had been driven by the sequence — reading a stale bus value from the previous transaction. Monitor and ref_model could latch different `awaddr` values in the same conceptual transaction because they hit their respective `else if` checks at different simulation times, and take different paths.

**Fix:** Restructured both monitor and ref_model to wait for `awvalid` first, then latch `awaddr`, then branch:
```
else begin
  wait(vif.awvalid == 1'b1);
  tr.awaddr = vif.awaddr;
  tr.awlen  = vif.awlen;
  ...
  if(vif.awaddr < 128) begin
    // valid burst path
  end
  else begin
    // error burst path
  end
end
```
**Verification:** Second run produced 0 MISCMP, 4 PASSED, err burst correctly tagged as `wrrderrfix` with `bresp:3/3 rresp:3/3`.

### Bug TB-6 — Coverage Class Structural Un-Closeable Bins Inflated Denominator

**Symptom:** Post-TB-5 clean run reported 72.92% coverage. Coverpoint drill-down showed `op_cp`, `burst_cp`, `addr_cp`, `bresp_cp`, `rresp_cp` all at 100%, but `id_cp` (16 individual bins for a 4-bit random field) at ~25% and off-diagonal cross bins (fixed × decerr, err × okay, valid_zone × decerr, error_zone × okay) all missing.

**Root cause:** Two independent modeling problems:
1. **`id_cp` bin granularity:** With only 4 valid bursts driven and `tr.id` a 4-bit random field, 16 individual bins were statistically unreachable. The `bins all_ids[] = {[0:15]};` was aspirational, not achievable within stimulus budget.
2. **Cross bins unreachable by design:** The stimulus contract is that `fixed`/`incr`/`wrap` operations target valid addresses (bresp = okay) and `err_fix` targets addr=128 (bresp = decerr). Off-diagonal combinations cannot be produced by any legal sequence. These bins were being counted as coverage holes when they should have been marked as structurally unreachable.

**Fix:** Two changes in `axi_coverage.covergroup`:
1. Reduced `id_cp` from 16 bins to 2 bucketed bins:
   ```
   id_cp: coverpoint tr.id {
     bins low_id  = {[0:7]};
     bins high_id = {[8:15]};
   }
   ```
2. Added `ignore_bins` to the three cross coverpoints to mark structurally unreachable combinations:
   ```
   op_x_bresp: cross op_cp, bresp_cp {
     ignore_bins ig1 = binsof(op_cp.fixed)   && binsof(bresp_cp.decerr);
     ignore_bins ig2 = binsof(op_cp.incr)    && binsof(bresp_cp.decerr);
     ignore_bins ig3 = binsof(op_cp.wrap)    && binsof(bresp_cp.decerr);
     ignore_bins ig4 = binsof(op_cp.err_fix) && binsof(bresp_cp.okay);
   }
   ```
   Same pattern applied to `op_x_rresp` and `addr_x_bresp`.

**Verification:** Coverage jumped from 72.92% → 94.44%. The residual ~5.56% gap is a single 4-bit random draw missing one of the two `id_cp` buckets (statistical, not structural).

## 5. Bugs Found in DUT

### DUT-1 — `wstate` FSM Does Not Return to `widle` Between Consecutive Bursts of Different Burst Types

**Symptom:** After a Fixed burst completed cleanly, the very next burst (INCR or WRAP) hung the driver — DUT's `wstate` FSM appeared to be stuck in a mid-burst state and did not accept the new burst's `wvalid` handshake.

**Root cause:** The DUT's `wstate` FSM has no explicit `bstate → widle` synchronization on burst completion. When `bready` fires and `bstate` returns to `bidle`, `wstate` remains in whatever state it was in at the end of the previous burst. A new burst starting immediately hits the FSM in the wrong state.

**Workaround (TB-side):** In `test.run_phase`, inserted a `rst_seq.start(e.a.seqr)` before every burst-type transition:
```
rst_seq.start(e.a.seqr);
fixed_seq.start(e.a.seqr);
rst_seq.start(e.a.seqr);
incr_seq.start(e.a.seqr);
rst_seq.start(e.a.seqr);
wrap_seq.start(e.a.seqr);
rst_seq.start(e.a.seqr);
err_seq.start(e.a.seqr);
```
The reset flushes all four FSMs (`awstate`, `wstate`, `bstate`, `rstate`) back to their idle states, allowing the next burst to start cleanly.

**Recommended DUT fix:** Add a synchronization edge in the `bstate` FSM's `bidle` transition to force `wstate` back to `widle`. This would eliminate the need for reset between bursts and allow back-to-back bursts of different types — a fundamental capability of a well-designed AXI slave.

**Impact:** The current workaround forces a 5-cycle reset per burst transition, which is functionally sufficient but breaks the AXI protocol assumption that a slave supports back-to-back bursts without external intervention. Coverage was also affected — the `id_cp` bucket coverage is limited to 4 unique IDs across 4 bursts rather than the higher stimulus budget a proper back-to-back scheme would allow.

### DUT-2 — Duplicate `interface axi_if()` in RTL File

**Symptom:** Elaboration would have failed with duplicate scope error after fixing DUT-3. Interface `axi_if` was declared at the bottom of `rtl/axi_rtl.sv` (after the `axi_slave` module's `endmodule`) and also in the authoritative `assertions/axi_sva.sv`.

**Fix:** Deleted the entire `interface axi_if() ... endinterface` block at the bottom of `rtl/axi_rtl.sv`. Interface is authoritative only in `assertions/axi_sva.sv`.

**Verification:** Re-compile clean.

### DUT-3 — State Typedefs Used Before Declaration (`wstate`, `bstate`, `arstate`, `rstate`)

**Symptom:** Compile error at RTL line 65:
```
ERROR: [VRFC 10-3380] identifier 'wstate' is used before its declaration
```
The `always_ff` reset block at line 63 assigned to `wstate`, `bstate`, `arstate`, and `rstate` before their `typedef enum` and `<type> <name>, <name>;` declarations appeared later in the module body.

**Root cause:** RTL author wrote FSMs bottom-up. Each FSM's typedef sits immediately above its `always_comb` block, which is far below the top-of-module reset block that references all four state variables.

**Fix:** Moved all four typedef+declaration pairs to a consolidated block immediately after the top-of-module signal declarations, before the reset `always_ff`. Deleted the original scattered declarations at their per-FSM sites.

**Verification:** Clean compile after consolidation.
